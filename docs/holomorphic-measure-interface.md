# Holomorphic measure interface reconciliation

SUN HOLO-GPU-REPAIR-01: https://github.com/isomorphisms/flexible-pipes/issues/227

The coordinate/tuple lineage and the Holomorphic colour-interface lineage have
one common implementation of Wegert colour conversion. `rational_measure`
exports a two-component shader carrier whose components mean phase in radians
and natural logarithm of modulus, in that order. `wegert_rgb_from_measure`
consumes that carrier. `wegert_rgb` delegates to those same functions. A shader
tuple is a numerical carrier, not a definition of a complex number.

This reconciliation retains the tuple lineage's `ShaderFloatTuple` and named
component operations. It preserves the colour constants and does not add an
`SVec` compatibility alias. Consumers must migrate their source and prove their
own generated byte selection before adopting this compiler revision.

The maintained `Example.SharedFactorPortrait` imports both public functions
from a different module. The existing `check_shared_factor_portrait.py` compiles
that consumer and checks the emitted interfaces, bounded loops, mathematical
operations and colour constants. Other maintained examples continue exercising
the `wegert_rgb` convenience entry. An export disappearing therefore fails the
compiler check rather than silently selecting a duplicate colour implementation.

This API repair does not repair cancellation in the shared rational evaluator.
Holomorphic owns exact divisor reduction before phase/log evaluation. It must
also independently qualify its polynomial, numerical ranges and singularities.

Local compilation is NOT_RUN until the pinned Idriç compiler/API and generated
backend executable are materialized. This source reconciliation is not shader
emission, Android packaging, framebuffer parity or physical GPU acceptance.
The application keeps its qualified compiler baseline until coordinated
source/API generation and independent acceptance pass.
