## Actual implementation

The inherited GLSL failure was already repaired by [fuego-ironworks/idris-shader-backend
PR #68, Compile shader runner ÷ and restore structured-IR acceptance](https://github.com/fuego-ironworks/idris-shader-backend/pull/68),
head `e7556cdb948f8ed039d612e703ce1b0c6030ee68`. This branch incorporates that
preserved emitter, matching generated outputs, real bounded-loop assertions,
negative fixtures and ICK runner selection with ancestry retained. The complete
GLSL suite is executed again; changing a golden alone was not the repair.

`ptx-backend.ipkg` registers a real compiler. Ordinary checked source passes
through the existing signature checker and indexed shader IR to complete PTX
8.8. A genuine Givens rotation and polynomial/pixel kernel assemble with CUDA
12.9.86 for `sm_80`, `sm_90`, `sm_100` and `sm_103`. Structured branch work is
guarded. Explicit F32 instructions use nearest rounding, without `.ftz` or FMA.
Unsupported widths, suffixes, loops and approximate/transcendental operations
are refused. These are per-sample compute buffers, not a CUDA fragment stage.

`amd-backend.ipkg` registers a separate real compiler for a bounded F32 pixel
slice. Checked source produces LLVM IR, native assembly and a linked AMDGPU
code object. The earlier LLVM 19.1.1 boundary is superseded by actual ROCm
7.2.3 LLVM 22 assembly/link acceptance for `gfx942`, `gfx950` and `gfx1250`.
Straight-line arithmetic, vec2 inputs,
scalar uniforms and exactly representable literals 0, ±1, ±2 are admitted.
Other literals and control flow are refused. A 64-thread workgroup is explicit;
on wave64 targets it occupies one wave, and on wave32 gfx1250 it occupies two.
No shader operation assumes a subgroup width. Host/device launch and
readback remain unverified for both vendors.

## Numerical evidence

`Backend.Numeric.Formats` defines OCP E4M3/E5M2, AMD FNUZ E4M3/E5M2, FP4 E2M1
and FP6 E2M3/E3M2. Finite scalars are exact integers in units of 2^-17. Rational
conversion uses nearest ties-to-even and explicit saturation; signed zero,
NaN, infinity, underflow, overflow and invalid widths stay distinct. OCP/FNUZ
reinterpretation is rejected; conversion is explicit. Six definitional proofs
check exceptional encodings and incompatible storage roles.

The separate checked-Ithon/ml_dtypes 0.5.3 oracle passes 1,168 scalar encodings,
1,716 adjacent midpoint/below/above cases and 904 finite-operand arithmetic
cases. Arithmetic here means exact mathematical operation followed by one
explicit requantization. It is not native GPU FP8 arithmetic, a proof of F32
intermediate-rounding equivalence or exceptional-input arithmetic acceptance.

MX decoding retains a 32-element block and its E8M0 scale with an unbounded
dyadic exponent, including extreme scales and NaN. MX native arithmetic and
UE5M3 codec acceptance are unverified. Scalar-only use of MX payloads,
experimental signed nine-bit E5M3 and NVIDIA unsigned eight-bit UE5M3 scales is
refused. Similar names do not authorize shared bits.

## Reproduction

Resolve the source checkout explicitly, then run the root Ikefile's `check`,
`numeric`, `qualify-nvidia` or `qualify-amd`. Supply verified absolute program
paths and the optional Grease recipe runner. Set `IKE_RECEIPT` and a caller-
computed `IKE_IKEFILE_IDENTITY=sha256:<actual Ikefile digest>`. Retain compiler,
SDK, source and artifact identities; a changed pin makes earlier evidence stale.

Independent gates: ai-ci `fada3841bc119c9b64e4076a56b2dffedf0a9d8b`, Ithon
`9d530f4ad51f5b0a09c3e74dbe45cac5bb6d52d3`, foreign ml_dtypes 0.5.3. Use
`verify_ike.pi` with the real runner and the appropriate `ci/gpu-plans/*.tsv`;
use `verify_numeric.pi` on the actual successful producer stream.
`self_test.grease` uses explicit environment inputs and actual damaged controls.
These gates cannot manufacture source provenance or GPU execution from arbitrary
caller-supplied TSV. See the [hardware matrix](gpu-hardware-matrix.md) and
`ci/gpu-follower-evidence/` for exact identities and unresolved obligations.
